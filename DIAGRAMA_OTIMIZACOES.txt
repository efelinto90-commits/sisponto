## 🔍 DETALHE: O QUE ACONTECE EM CADA QUERY

### ANTES: Sequential Scan (Varredura Completa)
```
Query: SELECT * FROM registros WHERE data = '2026-05-04'

╔════════════════════════════════════════════════════╗
║ Sem índice: PostgreSQL varre TODA a tabela        ║
╠════════════════════════════════════════════════════╣
║                                                    ║
║  Tabela: registros (500.000 linhas)                ║
║  ┌────┬────┬────┬────┬────┬────┬────┬────┐       ║
║  │ 1  │ 2  │ 3  │ 4  │... │497K│498K│499K│ Check ║
║  └────┴────┴────┴────┴────┴────┴────┴────┘        ║
║   ☑   ✗   ✗   ✗  ✗✗✗  ✗    ✗    ✓    Cada um! ║
║                                                    ║
║  Tempo: ~800ms (Ler 500K linhas)                   ║
║                                                    ║
╚════════════════════════════════════════════════════╝
```

### DEPOIS: Index Scan (Direto ao Ponto)
```
Query: SELECT * FROM registros WHERE data = '2026-05-04'
       (Com índice: idx_registros_data)

╔════════════════════════════════════════════════════╗
║ Com índice B-tree: PostgreSQL usa árvore indexada ║
╠════════════════════════════════════════════════════╣
║                                                    ║
║       Índice B-tree (data)                         ║
║                    2026-04-15                      ║
║                    /          \                    ║
║            2026-04-01      2026-05-01 ◄─ Vai aqui!║
║            /      \            /      \            ║
║       04-01  04-08  05-01  05-08 ◄─ Encontra!    ║
║       /  \   /  \   / \   / \                      ║
║    [data array com 150 registros]                  ║
║                                                    ║
║  Tempo: ~30ms (Acesso direto!)                     ║
║                                                    ║
╚════════════════════════════════════════════════════╝

GANHO: 800ms → 30ms = 96% mais rápido ⚡
```

## 🎯 CACHE STRATEGY (Session)

```
┌─────────────────────────────────────────────────────┐
│ SESSION CACHE (Tempo de vida: duração da sessão)    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  Login do usuário                                   │
│     │                                               │
│     ▼                                               │
│  ┌──────────────────────────────────────┐          │
│  │ session_start()                      │          │
│  └─────────┬────────────────────────────┘          │
│            │                                       │
│  Primeira Request:                                 │
│     ├─► if (!isset($_SESSION['horarios']))         │
│     │        └─► Query: SELECT * FROM horarios     │
│     │            Result → $_SESSION['horarios']    │
│     │            ✅ Cache criado!                   │
│     │                                              │
│  Segunda Request (mesma sessão):                   │
│     ├─► if (isset($_SESSION['horarios']))          │
│     │        └─► $horarios = $_SESSION['horarios'] │
│     │            ✅ SEM QUERY! (40x mais rápido)   │
│     │                                              │
│  Logout:                                           │
│     └─► Cache destruído (session_destroy())        │
│                                                    │
│  Ganho: 30ms → 1ms por request ✅                  │
│                                                    │
└─────────────────────────────────────────────────────┘
```

## 🎓 PRINCÍPIOS APLICADOS

```
1️⃣  INDEX EARLY
    └─ Criar índices em colunas de filtro/join
    
2️⃣  PREFETCH DATA
    └─ Buscar dados uma vez, reusar em loops
    
3️⃣  CACHE AGGRESSIVELY
    └─ Armazenar dados imutáveis em session
    
4️⃣  BATCH OPERATIONS
    └─ Uma query > múltiplas queries
    
5️⃣  SELECT SPECIFIC
    └─ SELECT campos_necessarios (nunca *)
    
6️⃣  COMPRESS OUTPUT
    └─ GZIP tudo quanto é texto
    
7️⃣  MONITOR ALWAYS
    └─ pg_stat_statements, slow queries
    
8️⃣  DOCUMENT WELL
    └─ Deixar comentários no código
```
